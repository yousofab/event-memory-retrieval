# مرحلهٔ دوم — خط پایهٔ بازیابی روی توسعه

تاریخ اجرا: ۱۴۰۵/۰۷/۱۵ (۷ اکتبر ۲۰۲۶). این مرحله فقط سه مکالمهٔ توسعه را استفاده می‌کند؛ هفت مکالمهٔ آزمون همچنان کنار گذاشته شده‌اند. فایل خروجی `results/phase2_development_baselines.json` شامل نتیجهٔ تک‌پرسش و خلاصهٔ تفکیکی مکالمه است.

## اجرای تکرارپذیر

```bash
python scripts/fetch_data.py
python scripts/audit_data.py
python -m unittest discover -s tests -v
python scripts/run_baselines.py
```

کد فقط به کتابخانهٔ استاندارد Python 3.9+ نیاز دارد. هش SHA-256 داده پیش از اجرا با قرارداد مرحلهٔ اول سنجیده می‌شود. اجرای پیش‌فرض: قطعهٔ ثابت تا ۱۲۸ واژهٔ متن، بودجه‌های ۵۱۲، ۱۰۲۴ و ۲۰۴۸ واژه. این اندازه‌ها **برای توسعه آزمایشی هستند** و پارامترهای آزمون نهایی پس از مرحلهٔ سوم ثبت می‌شوند.

## دو روش پایه و قرارداد مشترک

- `fixed`: قطعه‌کردن نوبت‌های متوالی درون هر جلسه، تا سقف ۱۲۸ واژه؛ نوبت شکسته نمی‌شود. اگر یک نوبت از سقف بلندتر باشد، به‌تنهایی در قطعه قرار می‌گیرد.
- `session`: تمام نوبت‌های یک جلسه در یک قطعه؛ هیچ متن جمع‌بندی آماده‌ای استفاده نمی‌شود.
- فقط متن نوبت‌ها با عبارت منظم Unicode `\w+` و حروف کوچک به واژه تبدیل می‌شود. نام گوینده و تاریخ جلسه به متن امتیازدهی افزوده نمی‌شود. طول نیز فقط شمار همین واژه‌هاست.
- هر دو روش با BM25 یکسان (`k1=1.2`, `b=0.75`) رتبه‌بندی می‌شوند. در امتیاز برابر، ترتیب قطعه‌ها در مکالمه تعیین‌کننده است. واژه‌های تکراری پرسش در امتیازدهی یک‌بار لحاظ می‌شوند. از بالای رتبه‌بندی، قطعه‌ای که به بودجهٔ باقیمانده جا شود انتخاب و قطعهٔ بزرگ‌تر رد می‌شود؛ قطعه بریده نمی‌شود و حتی قطعه‌های دارای امتیاز صفر می‌توانند فضای باقی‌مانده را پر کنند.
- شناسه‌های شاهد فقط پس از بازیابی برای سنجش به کار می‌روند. یک پرسش زمانی موفق است که **تمام** نوبت‌های شاهد آن در قطعه‌های انتخابی باشند. پاسخ مرجع، `event_summary`، `session_summary` و `observation` وارد مرزبندی یا رتبه‌بندی نمی‌شوند.

## مشاهدهٔ آزمایشی

| بودجهٔ واژه | ثابت: موفق از ۲۷۴ | جلسه: موفق از ۲۷۴ |
|---:|---:|---:|
| ۵۱۲ | ۲۰۱ | ۷۷ |
| ۱۰۲۴ | ۲۲۰ | ۱۸۳ |
| ۲۰۴۸ | ۲۳۱ | ۲۱۵ |

هر سه مکالمه در هر بودجه برای روش ثابت نرخ بالاتری دارند. این **نتیجهٔ توسعه** برای انتخاب و بررسی ابزار است؛ برتری تعمیم‌پذیر یا یافتهٔ نهایی پایان‌نامه نیست. واحد تحلیل مقایسه‌ای مکالمه است و تنها سه مکالمهٔ توسعه برای استنباط کافی نیستند. روش جلسه در بودجهٔ ۵۱۲ به علت بزرگی بسیاری از جلسه‌ها فضای کمتری را مصرف می‌کند (مثلاً میانگین مصرف در `conv-43` حدود ۴۰۲ واژه در برابر ۵۰۸ واژه برای ثابت). این اثر محدودیت «قطعهٔ کامل» باید در تحلیل نهایی بیان شود.

## نقطهٔ کنترل بعدی

پیاده‌سازی مرزبندی سبک رویدادمحور بدون برچسب پرسش، مقایسه روی همین سه مکالمه، ثبت اندازهٔ قطعه و بودجهٔ نهایی، سپس فقط یک‌بار اجرای آزمون کنارگذاشته‌شده.
