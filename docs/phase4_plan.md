# قرارداد آزمون نهایی پیش از مشاهدهٔ برچسب‌های آزمون

این فایل همراه با `scripts/run_held_out.py` و `configs/phase4_analysis_plan.json` **پیش از اجرای آزمون نهایی** در یک کامیت مستقل ثبت می‌شود. خروجی آن کامیت برچسب `phase4-analysis-plan` خواهد داشت. داده و فهرست پرسش‌ها با هش مرحلهٔ اول، و تنظیمات با هش فایل تثبیت‌شدهٔ مرحلهٔ سوم کنترل می‌شوند.

## روش مقایسه

سه روش قطعهٔ ثابت ۱۲۸ واژه، جلسهٔ کامل و مرزبندی تغییر واژگانیِ منتخب (پنجرهٔ ۳ نوبت، کمینهٔ ۶۴ و بیشینهٔ ۱۶۰ واژه) با BM25 یکسان اجرا می‌شوند. بودجهٔ اصلی ۱۰۲۴ واژه است؛ بودجه‌های ۵۱۲ و ۲۰۴۸ واژه تحلیل ثانویه هستند. قطعه‌ها بریده نمی‌شوند. پرسش و برچسب شاهد در مرزبندی وارد نمی‌شود؛ شناسهٔ شاهد فقط پس از انتخاب قطعه‌ها برای امتیازدهی استفاده می‌شود. نتیجهٔ آزمون هیچ تنظیمی را تغییر نخواهد داد.

معیار اصلی نرخ یافتن **تمام** شاهدهای هر پرسش است. برای هر یک از هفت گفت‌وگو نرخ محاسبه و اختلاف رویدادمحور منهای ثابت ثبت می‌شود. خلاصهٔ اصلی، میانگین بدون وزن این هفت اختلاف است. شمار موفقیت از ۵۹۹ پرسش فقط توصیفی است. آزمون دقیق وارون‌سازی علامت دوطرفه روی اختلاف‌های هفت گفت‌وگو به‌عنوان تحلیل اکتشافی گزارش می‌شود؛ با این تعداد کم، قدرت استنباط محدود است.

## تحلیل‌های ثانویه و هزینه

نتیجه برای هر روش و بودجه به تفکیک گفت‌وگو و، در بودجهٔ اصلی، به تفکیک دستهٔ پرسش، تعداد شاهدها و پراکندگی شاهدها در چند جلسه ثبت می‌شود. مواردی که فقط یکی از روش ثابت و رویدادمحور موفق است شمارش می‌شوند؛ این تحلیل توصیفی است و به بازتنظیم روش منجر نمی‌شود. نمایهٔ هزینه شامل تعداد قطعه‌های قابل امتیازدهی، تعداد کل واژه‌های ورودی، میانگین واژه و قطعهٔ بازیابی‌شده است. زمان اجرا یا هزینهٔ سرویس خارجی معیار اصلی نیست؛ این پیاده‌سازی به API پولی یا GPU نیاز ندارد.

## اجرای کنترل‌شده

```bash
python -m unittest discover -s tests -v
python scripts/run_held_out.py --run-held-out
```

اسکریپت اگر فایل نتیجه از قبل وجود داشته باشد، از بازنویسی آن جلوگیری می‌کند. فایل خروجی فقط شناسه‌ها و شمارها را ثبت می‌کند، نه متن گفت‌وگو یا پرسش‌ها.
